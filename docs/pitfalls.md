# Грабли (каждая уже стоила сломанного запуска или ложной блокировки)

Читать перед правкой логики стража/сторожа. Питфолы сгруппированы по платформам.

## Bash / Linux

1. **`~/.local/bin/claude` может быть симлинком на бинарь Claude Code** (243 МБ, ещё и
   жёсткая ссылка внутри `node_modules`). Запись через `>` уходит **по ссылке** и затирает
   сам бинарь: Claude перестаёт запускаться (симптом — бесконечная рекурсия «обёртка →
   бинарь → обёртка», команда висит). Только `rm -f` перед записью + проверка, что целевой
   файл — исполняемый ELF > 1 МБ (`real_is_sane`). Восстановление:
   `npm install -g @anthropic-ai/claude-code --force`.
2. **`pgrep -f <шаблон>` ловит собственные команды** (матчится вся командная строка).
   В разовом прогоне «нашлось» 15 процессов Claude, из которых настоящих не было: это были
   строки самого теста. Проверять гашение только на подсадной утке с суженным
   `WATCH_PATTERNS`, иначе **сторож реально закрывает запущенный Desktop** (так и случилось).
3. **`$(run_checks …)` — подпроцесс:** переменная с причиной отказа в родителе теряется.
   Путь запуска печатал общий совет («включи VPN») даже когда блок был по региону.
   Причину писать в файл состояния (`last-reason`) и читать после вызова.
4. **Время из логов Desktop** парсить через UTC-эпоху
   (`SpecifyKind($d, Local).ToUniversalTime()`; в bash `date -d` + `%s`), иначе получается
   сдвиг на часовой пояс: жалоба 3-часовой давности выглядела «из будущего» и старой её
   признать было нельзя.
5. **Выходной IP мерить только туннельными источниками** — `1.1.1.1/cdn-cgi/trace`,
   `claude.ai/cdn-cgi/trace`. При сплит-туннеле `api.ipify.org`, `checkip.amazonaws.com`
   и даже `www.cloudflare.com` уходят НАПРЯМУЮ и показывают домашний РФ-адрес: проверка
   обманывается, а «плохим» помечается не тот IP.
6. **Проба IP бывает транзиентно пустой** (лимит/таймаут) → делать 2 попытки с паузой 2 с.
   Иначе страж впустую отказывает, а сторож не помечает плохой выход.
7. **`--version` / `--help` идут мимо проверок** (быстрый путь). Симуляции на них не видны:
   отказ проверять на живом запуске (`claude -p "тест"`).
## PowerShell / Windows

8. **У скрипта-обёртки НЕ должно быть `param(...)`:** PowerShell перехватывает
   `claude -p "текст"` как свой параметр (`-p` → ambiguous: `-ProgressAction`), и Claude
   Code не запускается. Аргументы разбирать вручную из `$args`, свои ключи отсеивать.
9. **`$rc = Fn *> $null` съедает возвращаемое значение** (успешный поток тоже
    перенаправляется) → самопроверка врала на кейсе «норма». Гасить `Write-Host` через
    `6>$null`, результат функции — в переменную.
10. **Типы WinForms в теле функции роняют скрипт ДО `try`:** PowerShell разрешает
    `[System.Windows.Forms.NotifyIcon]` при JIT, инициализатор кидает
    `TypeInitializationException` мимо `catch`. Уведомление собирать строкой и вызывать
    через `[scriptblock]::Create($code).Invoke()` внутри `try` + ранний выход, если
    `$env:OS -ne 'Windows_NT'`.
11. **Шим `claude.cmd` — только CRLF, без BOM, заголовок ASCII** (LF-only батник в cmd.exe
    молча не работает). Проверять байтами, а не глазами.
12. **Порядок `PATH`:** шим должен идти раньше `%APPDATA%\npm`, иначе npm-версия выигрывает.
    Держит это не порядок сам по себе, а задача самолечения `ClaudeGuardHeal`.
13. **Claude Desktop из Store (MSIX) перехватить нельзя** — только ярлык + сторож.
14. **Проверка вердикта Anthropic без Claude Desktop пуста:** в WSL/на машине без Desktop
    жалоб в логах нет, проверка пропускает. Это нормально, но не путать с «проверка сломана».

## Тесты

15. **`Join-Path $HOME 'state\file'` на Linux** даёт литеральный обратный слэш → проверка
    «файл появился» ложно падает. Соединять по одному сегменту или `[IO.Path]::Combine`.
16. **Сеть в проверках капризна:** одиночный транзиентный сбой пробы даёт ложный FAIL.
    В тестах — до 3 попыток, проверка по факту успеха.
17. **Харнесс обязан работать в песочнице** (`CLAUDE_GUARD_HOME` / `CLAUDE_GUARD_STATE`),
    иначе он пишет в реальное состояние и может пометить рабочий выход плохим.

18. **Проверки IPv4 не видят глобальный маршрут IPv6.** Туннель IPv4 поднят, страна не РФ —
    а трафик к узлу с AAAA-записью уходит напрямую с реального IPv6-адреса. Перед стартом
    искать `::/0` мимо туннеля (`ip -6 route`, `Get-NetRoute -AddressFamily IPv6`); нет
    глобального маршрута IPv6 — норма, а не поломка.
19. **Тесты ошибаются теми же руками.** «Свежие» кейсы юнит-тестов проходили, потому что
    подставные метки времени генерировались на 30 с **в будущем** (`AddSeconds(+30)` вместо
    `-30`): из-за fail-closed страж считал их свежими. Знак смещения задавать явно и
    проверять оба края каждого окна (±10 с), а не только середину.
20. **Документация расходится с кодом тихо.** В `how-it-works` окно `REGION_STALE` было
    описано как «отказ», а код выдавал **предупреждение**; расхождение нашли юнит-тесты.
    Править текст в том же коммите, что и логику.
21. **Тайм-аут пробы должен быть один на обе программы.** В Windows-стороже было
    захардкожено 10000 мс, в страже — `CLAUDE_GUARD_TIMEOUT` (12000 мс): при медленной сети
    поведение расходилось. Брать значение из одного места (и в шиме, и в стороже).
22. **Сообщения установщика сверять с фактическим деревом.** `install.ps1` отправлял
    пользователя в папку `wsl/`, которой в комплекте нет (Linux-комплект лежит в `linux/`).
    Пользователь уходит искать несуществующее — проверять пути в текстах.
23. **«Ярлык создан» проверять не по байтам.** `.lnk` — бинарный: «файл непустой» ничего не
    доказывает. Читать через `WScript.Shell` и сверять `TargetPath` / `Arguments`.
24. **Windows-специфику нельзя доказать эмуляцией.** `Get-NetAdapter`, `Find-NetRoute`,
    `Register-ScheduledTask`, `PATH` в реестре проверяются только на настоящей Windows
    (джоб `windows-native`, `tests/win-e2e.ps1`); в прогоне под Linux они честно пропускаются.

25. **`systemctl --user` не изолируется подменой `HOME`.** E2E установки/снятия в песочном
    `HOME` вызвал `install.sh --uninstall`, тот выполнил `systemctl --user disable --now` — и
    **остановил сторож на рабочей машине** (`is-active` → inactive, `is-enabled` → disabled,
    защита молча выключена). Дом у systemd один на пользователя: службами управлять только
    когда `systemd_ours` подтверждает совпадение `HOME`, а в тестах — `--no-systemd`.

26. **Windows PowerShell 5.1 читает `.ps1` без BOM как ANSI.** Файл с кириллицей превращается
    в мусор (`ÐºÐ¾Ð¼Ð¿Ð»ÐµÐºÑ‚`), а если испорченные байты попадают в синтаксис — скрипт вообще не
    парсится: `Unexpected token ':' in expression`. PowerShell 7 читает UTF-8 и без BOM, поэтому
    под Linux и в прогоне харнесса поломка **не видна** — она проявилась только в CI-джобе на
    настоящей Windows. Все `.ps1` с не-ASCII текстом держать с UTF-8 BOM
    (`scripts/ps1-ensure-bom.sh`, проверка в харнессе). Шимы `claude.cmd` / `claude.ps1`,
    наоборот, писать только ASCII (`UTF8Encoding($false)`) — им BOM не нужен и вреден.

27. **Проверка, зависящая от установленного приложения, обязана быть SKIP, а не PASS/FAIL.**
    Один и тот же урок стоил двух ложных провалов в CI: на раннере нет Claude Desktop, поэтому
    установщик законно не создаёт ярлык «Claude (с VPN)» (Windows) и не переопределяет
    `.desktop` (Linux). Тест, требующий их безусловно, падает на здоровой системе. Условная
    проверка + счётчик пропусков; в выводе — причина пропуска.

28. **В PowerShell `$src` и `$Src` — одна и та же переменная.** В `install.ps1` цикл писал
    `$src = Join-Path $Src $f`, то есть присваивал самому `$Src`: после первой итерации путь
    становился `...\windows\claude-guard.ps1`, и второй файл искался в
    `...\windows\claude-guard.ps1\claude-watchdog.ps1`. В итоге копировался **только первый
    файл**, задача Планировщика указывала на несуществующий `claude-watchdog.ps1`, а установщик
    рапортовал успех. Ловится только установкой на настоящей Windows (`tests/win-e2e.ps1`) —
    локальный харнесс вызывает стража напрямую и `install.ps1` не выполняет. Переменную цикла
    называть иначе (`$srcFile`) и не переиспользовать имена, отличающиеся лишь регистром.

29. **Пробник живости на API со сторонними лимитами врёт «нет VPN».** Выход мерился
    `ipinfo.io`: при частых проверках он отдаёт `HTTP 429 Rate limit hit`, проба оставалась
    пустой, и страж (fail-closed) отказывал с текстом «Нет VPN-туннеля или выход из РФ».
    766 проверок / 75 ложных отказов за 2.5 суток при живом туннеле, реальных гашений — 0.
    Вывод: брать источник без лимитов (Cloudflare trace отдаёт `ip=`/`loc=` строками) и
    мерить домен **целевого** сервиса (`claude.ai`), а не первый попавшийся: `www.cloudflare.com`
    сплит отправляет напрямую, и проба покажет домашний РФ-адрес.

30. **«Нет ответа» и «выход из РФ» — разные причины, и пользователю нужно видеть какую.**
    Общий текст «включи VPN» на любой отказ уводит диагностику в сторону. Причина пишется в
    `last-reason`, оттуда её берут и путь запуска, и сторож: пустые пробы дают `no-answer`,
    страна `RU` — `country`, вердикт Anthropic — `anthropic`, утечка IPv6 — `ipv6`.

31. **Фоновая проверка не должна уведомлять.** Сторож зовёт страж каждые ~2.5 мин: уведомление
    на каждый отказ превращается в спам «нет VPN» при живом туннеле. Фон идёт с
    `CLAUDE_GUARD_QUIET=1`, уведомление отправляет сторож и только по факту гашения. Порог
    полной проверки отдельный (`WATCH_GUARD_THRESHOLD=4`) — одиночный сбой сети не закрывает Claude.

32. **Тест, зависящий от сети, врёт (причём с обеих сторон).** Сначала «запасной пробник»
    проверялся живым запросом — падал при перегруженном канале; потом `file://` — в .NET
    `FileWebRequest` не принимает `UserAgent`, проба всегда пустая. Рабочий шов — каталог
    с телами ответов (`CLAUDE_GUARD_PROBE_FIXTURE`): файл по имени пробника (`trace`/`ipinfo`),
    нет файла = «не ответил». Сеть не нужна, а проверяется именно цепочка.

33. **Молчаливый пропуск полной проверки опаснее шума.** Сторож берёт страж по
    `$GuardHome\claude-guard.ps1` (туда файл кладёт `install.ps1`); если файла нет, сторож тихо
    проверял только туннель — то есть не ловил «туннель есть, а выход РФ». Теперь отсутствие
    файла пишется в `watchdog.log`, и в харнессе это отдельная проверка (сначала «не молчит»,
    потом — после копирования файла — что причина провала видна).
