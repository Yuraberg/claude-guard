# Как проверять

Всё, что можно, проверяется **без вреда для рабочей системы**: состояние стража и сторожа
уводится в песочницу (`CLAUDE_GUARD_STATE`, `CLAUDE_GUARD_HOME`, `CLAUDE_GUARD_LOGS_DIR`),
сетевой выход подставляется переменными, а «настоящий» Claude Code — фальшивым файлом
(ELF > 1 МБ в песочнице или PE > 1 МБ на Windows). VPN для юнит-тестов не нужен вообще.

| Набор | Что проверяет | Запуск | Проверок |
|---|---|---|---|
| `tests/bash-tests.sh` | Linux-ветку целиком: синтаксис, шим, симуляции стража, вердикт Anthropic, сторож | `./tests/bash-tests.sh` | 29 |
| `tests/unit-thresholds.sh` | пороги времени Linux-ветки — изолированно, без сети | `./tests/unit-thresholds.sh` | 25 |
| `tests/linux-install-e2e.sh` | установку и снятие в изолированном `HOME` (режим `--no-systemd`) | `./tests/linux-install-e2e.sh` | 21 (без Claude Desktop часть шагов SKIP) |
| `tests/unit-thresholds.ps1` | пороги времени Windows-ветки — изолированно, без сети | `pwsh -NoProfile -File tests/unit-thresholds.ps1` | 29 |
| `tests/win-guard-harness.ps1` | Windows-ветку без Windows: кодировка `.ps1` (BOM), шим (CRLF/ASCII), симуляции, вердикт, гашение процессов | `pwsh -NoProfile -File tests/win-guard-harness.ps1` | 32 |
| `tests/win-e2e.ps1` | установку на **настоящей Windows**: Планировщик, `PATH` в реестре, `Get-NetAdapter`/`Find-NetRoute`, ярлык, снятие | `powershell -File tests/win-e2e.ps1` | 31 |

## Юнит-тесты порогов (без сети)

Самая ценная часть для будущих правок: логика «какая жалоба Anthropic относится к текущему
выходу» проверяется на границах, а не «на глазок». Обе ветки берут функции в режиме
библиотеки (`CLAUDE_GUARD_SOURCE_ONLY=1`, в PowerShell — тот же переменной окружения) и
создают логи Desktop с нужными отметками времени в песочнице.

Что утверждается явно:

- разбор отметки времени и «сейчас» (ловит сдвиг часового пояса: раньше 3-часовая жалоба
  выглядела «из будущего»);
- свежая жалоба (≤ `REGION_FRESH`) → **отказ** и пометка текущего IP плохим;
- ровно на границе свежести (±10 с) — включая то, что IP помнится;
- жалоба 120–900 с (`REGION_STALE`) → **пропуск с предупреждением «есть след»**, без
  блокировки и без пометки IP (иначе после смены узла страж отказывал бы ещё четверть часа);
- жалоба старше 900 с → игнорируется целиком (в том числе не упоминается в выводе);
- отметка «из будущего» (сбитые часы) → отказ, а не пропуск (fail-closed);
- слабый сигнал: серия 403 (`API403_MIN` за `API403_FRESH`) — только предупреждение,
  одиночный 403 и старые 403 — молчание;
- память плохих выходов: запись, отсутствие дублей, отказ держится **и когда логов уже нет**,
  сброс памяти возвращает пропуск;
- режим CLI: вердикт Anthropic не проверяется.

## Linux-ветка (в песочнице)

`tests/bash-tests.sh` дополнительно проверяет синтаксис скриптов, `--self-test` (6
симуляций), совет «смени узел» в пути запуска и запись `reason=anthropic` в журнал, игнор
старой жалобы, `--mark-blocked` / `--reset-web-block`, реакцию сторожа на жалобу (dry-run).

Проверки, зависящие от установленных приложений, честно **пропускаются** (`SKIP`), а не
проходят впустую: без Claude Desktop в системе переопределять нечего, и установщик этот шаг
тоже пропускает. В CI раннер Desktop не имеет — соответственно `SKIP`.

`tests/linux-install-e2e.sh` ставит комплект в пустой `HOME` так же, как это делает
пользователь в WSL (`install.sh --no-systemd`), проверяет, что обёртка `~/.local/bin/claude`
**действительно блокирует** живые запуски (симуляции `ru-exit`, `no-tun`), что переопределён
`.desktop` для Claude Desktop, что службы systemd в этом режиме не ставятся, и что `--uninstall`
возвращает систему в исходное состояние (логи при этом остаются).

## Windows-ветка под Linux (без Windows)

Нужен портативный PowerShell 7.4.6 (root не нужен):

```bash
mkdir -p /tmp/pwsh && curl -fL --retry 3 -o /tmp/pwsh.tar.gz \
  https://github.com/PowerShell/PowerShell/releases/download/v7.4.6/powershell-7.4.6-linux-x64.tar.gz
tar -xzf /tmp/pwsh.tar.gz -C /tmp/pwsh          # качать в ФАЙЛ, не в пайп — рвётся
/tmp/pwsh/pwsh -NoProfile -File tests/win-guard-harness.ps1
```

Харнесс подкладывает фальшивый «настоящий» Claude Code в песочный `%LOCALAPPDATA%`,
поэтому рабочая машина не затрагивается. Проверяет: синтаксис всех `.ps1`, **наличие UTF-8 BOM
там, где в `.ps1` есть кириллица** (иначе Windows PowerShell 5.1 читает файл как ANSI и падает
с `Unexpected token`; PowerShell 7 эту поломку не показывает), шим (CRLF/ASCII),
6 симуляций стража, отказ при выходе РФ / без туннеля / при вердикте Anthropic / при утечке
IPv6, живой запуск настоящего бинаря, выбор и **реальное гашение** процесса (функции
принимают инъекцию `-ProcessList` / `-Victims`), разбор вердикта Anthropic из подложенных
логов, реакцию сторожа и `CLAUDE_GUARD_FORCE_REGION`.

## Настоящая Windows (E2E)

`tests/win-e2e.ps1` — единственный набор, который проверяет Windows-специфику, недоступную
при прогоне под Linux: `Get-NetAdapter`, `Find-NetRoute`, `Register-ScheduledTask`,
`PATH` в реестре, ярлык `.lnk`. Скрипт сам подкладывает «настоящий» `claude.exe` (копия
`cmd.exe`, добитая до 2 МБ — установщик отвергает мелкие файлы) и проходит путь
**установка → проверки → снятие**, как обычный пользователь:

- установщик возвращает 0, отчёт установки создан, шимы `claude.cmd` / `claude.ps1` /
  `claude-guard.cmd` / `claude-guard.ps1` на месте, каталог шима стоит в пользовательском
  `PATH` **первым**;
- зарегистрированы обе задачи Планировщика, ярлык ведёт на `claude-desktop-launch.ps1`
  (читается через `WScript.Shell`, а не «файл непустой»);
- `-Doctor`, `-Status` работают под **Windows PowerShell 5.1** (именно он есть у обычного
  пользователя), `-SelfTest` даёт 5 PASS по симуляциям; если в системе есть `pwsh` 7 —
  то же самое проверяется и в нём;
- отказ проверяется детерминированно симуляцией (`CLAUDE_GUARD_SIM=no-tun|ru-exit` через
  сам шим, вызовом `cmd.exe`), потому что на машине без VPN и без РФ-выхода настоящая
  проверка может законно разрешить запуск;
- `uninstall.ps1` снимает задачи, `PATH`, шимы и ярлык.

На Linux этот скрипт не запускается и честно сообщает об этом (код 2) — «эмулировать»
Windows-специфику он не пытается.

## Что всё ещё требует ручной проверки

- обрыв VPN **на живой машине**: гашение уже работающего Claude Desktop (в тестах процесс
  подставной);
- Claude Desktop из Microsoft Store (MSIX): перехват запуска ярлыком не проверяем
  автоматически;
- утечка DNS мимо VPN на уровне прокси-клиента (текущая проверка IPv6 ловит только
  глобальный маршрут IPv6);
- WSL со включённым systemd (в E2E используется режим `--no-systemd`, как в WSL без systemd).

## CI

То же самое гоняется в GitHub Actions (`.github/workflows/tests.yml`), три джоба:

- `linux` — `tests/bash-tests.sh`, `tests/unit-thresholds.sh`, `tests/linux-install-e2e.sh`;
- `windows-logic` (Ubuntu + предустановленный PowerShell) — `tests/unit-thresholds.ps1`,
  затем харнесс. Установленного Claude Code в CI нет, поэтому харнесс подкладывает
  синтетический ELF > 1 МБ и единственную зависящую от него проверку помечает `SKIP`
  (31 выполняется, 1 пропускается, провалов быть не должно);
- `windows-native` (`windows-latest`) — `tests/win-e2e.ps1` на живой Windows.

## Правила безопасности при тестах

1. Никогда не гонять симуляцию гашения по штатным шаблонам на рабочей машине: сторож
   закрывает запущенный Claude Desktop (уже случалось). Только подсадная утка + суженный
   `WATCH_PATTERNS` или `--dry-run`.
2. Харнесс и bash-тесты обязаны писать состояние в песочницу — иначе можно пометить
   плохим реальный выходной IP.
3. После прогона проверять, что рабочая система цела: `claude --version`,
   `claude-guard --status`, службы `is-active`, процессы Desktop на месте.
4. Сетевые проверки делать с повторами: одиночный транзиентный сбой пробы даёт ложный FAIL.
5. Тесты — тоже код: смещение времени в подставных логах задаётся **явным знаком**
   (положительное — назад, отрицательное — в будущем), иначе «свежие» кейсы проходят
   по счастливой случайности. В обеих ветках знак проверяется на границах.
6. **Подмена `HOME` не изолирует `systemctl --user`** (дом у systemd один на пользователя).
   Любой прогон установки/снятия в песочнице запускать с `--no-systemd`, иначе снятие
   отключит сторож на рабочей машине — так и случилось. После тестов проверять
   `systemctl --user is-active claude-desktop-tunnel-guard.service`.
