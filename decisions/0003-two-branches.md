# 0003. Две ветки комплекта и подмена в PATH вместо прокси

**Дата:** 04.10.2026

## Решения

1. Комплект ставится **подменой запуска**: обёртка `claude` в `PATH` (Linux) / шим
   `claude.cmd` + `.ps1` в начало пользовательского `PATH` (Windows). Не прокси, не
   перехват сети, не правка системных файлов хоста.
2. Две отдельные ветки: `windows/` (PowerShell) и `linux/` (bash, она же для WSL).
3. GUI-часть (Claude Desktop) закрыта **двумя** механизмами: запуск через ярлык с проверкой
   (`.desktop` / ярлык «Claude (с VPN)») **и** сторож, который гасит уже запущенный Claude.

## Почему подмена в PATH, а не прокси

- Прокси нужно настраивать в каждом инструменте, и он не отвечает на вопрос «а выпустит ли
  трафик мимо туннеля»; при сплит-туннеле именно мимо и уходит.
- Обёртка проверяет **состояние машины** перед стартом процесса: это ровно тот момент,
  когда риск максимален.
- Ставится без админа/root, ничего не ломает в системе, снимается одной командой
  (`--uninstall` / `uninstall.ps1`) и самовосстанавливается после npm-обновления.

## Почему две ветки

Механика платформ разная (systemd --user / Планировщик задач, `.desktop` / ярлык MSIX,
`ip route` / `Find-NetRoute`, bash / PowerShell), а логика проверок одна и та же.
Общий кусок — только текст проверок; попытка «единого скрипта» упёрлась бы в платформу.
Ветка `linux/` переносимая (HOME, бинарь Claude Code, VPN-интерфейс определяются на месте)
и годится для WSL — в WSL2 трафик всё равно NAT-ится через Windows, то есть через тот же VPN.

## Почему для Desktop два механизма

Store-приложение (MSIX) перехватить подменой запуска нельзя, поэтому:

- **до запуска** — только через ярлык, который зовёт проверку (`claude-desktop-guard`);
- **после запуска** — сторож: пропал туннель (2 провала ≈30 с) или пришла свежая жалоба
  Anthropic → Claude закрывается. Черновики при этом теряются — принято осознанно
  (см. `0001-fail-closed`).

## Следствия

- VS Code-расширение стражем не покрыто (защита только маршрутизацией). Записано в
  `context/threat-model.md`.
- Версия в проекте и на рабочей машине должна совпадать: правка → `install -m 755` в
  рабочие пути → прогон тестов.
