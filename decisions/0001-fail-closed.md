# 0001. Fail-closed, а не fail-open

**Дата:** 04.10.2026

## Решение

Любая неясность при проверке трактуется как запрет: нет туннеля, нет ответа на пробу,
страна РФ, IP неизвестен, Anthropic отклонил выход → запуск Claude отменяется, а
работающий Claude гасится сторожем.

## Почему

Цена ошибок несимметрична:

- **fail-open** (пропустить при сомнении): один запуск без VPN = запросы с российского IP
  в аккаунт, который живёт месяцами. Последствия необратимы (бан) и выясняются постфактум.
- **fail-closed** (не пустить при сомнении): пользователь видит отказ, читает причину и
  решает за минуту (включить VPN / сменить узел).

Асимметрия в пользу запрета: ложный отказ стоит минуты, ложный пропуск — аккаунта.

## Следствия

- Код проверок возвращает 1 при пустом/непонятном ответе проб (в т.ч. таймаут).
- Аварийный обход есть, но только ручной — `CLAUDE_GUARD_OVERRIDE=1`; факт обхода пишется
  в журнал, чтобы «почему оно прошло» всегда было видно.
- В CLI-режиме (`--check-cli`) 4-я проверка не выполняется: она про GUI-Desktop, а
  `api.anthropic.com` такой выход принимает. Основной режим (без флага) блокирует и CLI —
  приоритет «не рисковать аккаунтом» выше удобства.
