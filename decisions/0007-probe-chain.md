# 0007. Пробники выхода: цепочка Cloudflare trace, причина отказа видна, фон молчит

**Дата:** 06.10.2026

## Решение

1. Проба выхода идёт по цепочке (первый ответивший побеждает):
   1. `https://1.1.1.1/cdn-cgi/trace` — Cloudflare trace, строки `ip=` / `loc=`;
   2. `https://claude.ai/cdn-cgi/trace` — тот же trace с домена целевого сервиса;
   3. `https://ipinfo.io/json` — запасной, только последним.
   Адреса переопределяются переменными `CLAUDE_GUARD_PROBE_PRIMARY` / `_SECONDARY` / `_JSON`.
2. Причина отказа называется точно и пишется в `state/last-reason`:
   `no-answer` (ни один пробник не ответил), `country` (выход `RU`), `ipv6`, `tunnel`,
   `anthropic`. Текст уведомления берётся из причины, а не «нет VPN» на все случаи.
3. Фоновая проверка сторожа идёт с `CLAUDE_GUARD_QUIET=1` — уведомления шлёт только сторож
   и только по факту гашения.
4. У полной проверки отдельный порог (`WATCH_GUARD_THRESHOLD=4` против `WATCH_THRESHOLD=2`
   у проверки туннеля).
5. Пропавший файл стража пишется в `watchdog.log` (раньше проверка молча пропускалась).
6. Тестовый шов `CLAUDE_GUARD_PROBE_FIXTURE=<каталог>`: тело ответа пробника берётся из файла
   по имени пробника (`trace` / `ipinfo`), нет файла — «не ответил».

## Почему

На рабочей машине при **живом туннеле** периодически приходили уведомления «нет VPN-туннеля».
В журнале: 766 проверок за 2.5 суток, 75 отказов (`reason=country`, `country_proxy=?`),
реальных гашений — 0. Причина: проба шла на `ipinfo.io`, а он на бесплатном тарифе отдаёт
`HTTP 429 Rate limit hit`. Пустой ответ трактовался как «страна неизвестна» → fail-closed →
отказ → уведомление с текстом про VPN, которого не было. Пользователь видел ложные тревоги и
не мог отличить их от настоящего падения туннеля.

Второй эффект: уведомление уходило на **каждую** фоновую проверку (сторож зовёт страж каждые
~2.5 мин), то есть одна и та же ложная причина повторялась десятки раз.

## Следствия

- Пробник живости не должен зависеть от API со сторонними лимитами; Cloudflare trace лимитов
  не имеет и отдаёт `ip` + `loc` одной строкой.
- Мерить надо домен целевого сервиса (`claude.ai`): правило сплита может отправлять
  «удобный» домен напрямую, и проба покажет домашний РФ-адрес (питфол 5 в `docs/pitfalls.md`).
- `no-answer` — не то же самое, что «выход из РФ»: пользователю показывается разный текст,
  а сторож различает причины в журнале.
- Тесты цепочки пробников обязаны быть герметичными: живой запрос нестабилен, `file://` в
  .NET не работает (`FileWebRequest` не принимает `UserAgent`) — используется фикстура.
